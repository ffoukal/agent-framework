## What this is
`agent-framework` is the source repo that **develops and dogfoods itself**: an
installable, CLI-agnostic multi-agent protocol (Claude Code, Codex, OpenCode, ...).
Target repos run `install.sh` to get `AGENTS.md`, `.agents/` and generated adapters;
this repo is where that framework content is authored, then installed onto itself
(`./install.sh .`) so its own tasks (like TASK-001) exercise the real pipeline.

## Stack
POSIX shell (`install.sh`, `update.sh`, `detectors/*.sh`, `.agents/scripts/*`) and
Markdown (`AGENTS.md`, agent role files, templates, docs). No compiler, no package
manager, no test framework — correctness is shell syntax + protocol consistency
between the two copies of the framework content (see Gotchas).

## How to navigate this repo
- `framework/` — canonical framework payload, copied verbatim into target repos by
  `install.sh`/`update.sh`: `AGENTS.md`, `CLAUDE.md`, `.agents/agents/` (role files),
  `.agents/scripts/` (agent-task-* tooling, `agent-git-guard`, `agent-models-sync`),
  `.agents/templates/`, `.agents/skills/`, `.agents/README.md`, `.agents/VERSION`.
- `project-template/` — skeleton for the per-repo part (`.agents/project/`): blank
  `project.md`, `config.yml`, `memory/*.md`, all TODO-marked. Copied only if
  `.agents/project/` doesn't already exist.
- `detectors/` — `kotlin.sh`, `go.sh`, `node.sh`: pre-fill `project.md`/`memory/`
  drafts for repos matching those stacks. No shell/Markdown detector exists (this
  repo's own stack), which is why this task (TASK-001) had to be done by hand.
- `install.sh` — installs the framework + project template into a target repo.
- `update.sh` — refreshes framework files in a target repo; never touches `project/`,
  `tasks/`, or `current-task`.
- `docs/` — supporting docs (specs land under `docs/specs/` in installed repos).
- `.agents/` (this repo's own, dogfooded copy) — mirrors `framework/.agents/` plus
  this repo's own `tasks/` and `project/`.
- `.claude/agents/`, `.claude/commands/`, `.opencode/agent/`, `.opencode/command/` —
  **generated** subagent adapters and slash commands (see Gotchas).

## Build & test
There is no build. Verification is:
- `bash -n <script>` over every shell script (`install.sh`, `update.sh`,
  `detectors/*.sh`, `.agents/scripts/*`) to catch syntax errors.
- `./install.sh .` run from repo root as an end-to-end dogfood smoke test: installs/
  refreshes the framework onto this repo itself and should complete without error.
- `.agents/scripts/agent-task-check <task-id>` after any task-artifact edit, to catch
  unreplaced template placeholders and drift.

## Project-specific rules
- `framework/` is the single source of truth for framework content. This repo's own
  `.agents/agents|scripts|templates|skills`, `AGENTS.md`, `CLAUDE.md` are a dogfooded
  **copy** of `framework/`, kept in sync by running `./install.sh .` (or `update.sh .`)
  — never hand-edit the dogfooded copy to fix a framework bug; edit `framework/` and
  resync.
- Never hand-edit generated adapters: `.claude/agents/*.md`, `.claude/commands/*.md`,
  `.opencode/agent/*.md`, `.opencode/command/*.md`. They are regenerated by
  `.agents/scripts/agent-models-sync` from `.agents/agents/*.md` and
  `.agents/project/config.yml`. Edit the source files and rerun the sync.
- Task work in this repo touches `.agents/project/` and `.agents/tasks/` only, unless
  the task is explicitly about the framework itself (in which case it edits
  `framework/` and the change must be propagated via install/update, not by editing
  both copies independently).

## Gotchas
- **Dual-copy drift**: `framework/.agents/*` and this repo's own `.agents/*` (agents,
  scripts, templates, skills, AGENTS.md, CLAUDE.md) are two copies of the same
  content. They are currently identical (verified via `diff -rq`). A framework change
  must be made in `framework/` and then propagated by running `./install.sh .` — if
  someone edits the dogfooded `.agents/` directly, the two copies silently diverge.
- **Generated files look like normal Markdown**: `.claude/agents/*.md`,
  `.claude/commands/*.md`, `.opencode/agent/*.md`, `.opencode/command/*.md` have no
  strong visual marker in a casual read; check for a generator marker/comment before
  editing, or just don't edit them — treat the whole directory as build output.
- `config.yml`'s `models.mapping` has placeholder `<provider/model>` / `<model>`
  entries for `opencode`/`codex` — only `claude-code` mappings are filled in.
